# 网页端 2.5D 上下点头（HeadPitch）实施计划

## 1. 目标与结论

本计划在现有 `mesh-turn.html` 左右转头原型上增加上下点头能力，并保持当前手工曲面方案的核心原则：

- 不是把整张头像当平面做缩放、倾斜或圆柱投影。
- 先用统一的 3D 曲面完成基础透视，再对脸型、五官、头发和遮挡关系分别做艺术校正。
- 保留 A/B 对照：A 只展示数学旋转，B 展示数学旋转加手工关键形。
- 正面必须与当前基线严格一致；新增点头不能破坏已完成的左右转头。
- 第一版只追求当前素材可支持的自然小幅点头，不用过度形变伪装大角度。

建议把稳定工作范围控制在：

- 抬头：约 `7°`。
- 低头：约 `8°`。
- 调试时可以暂时放大到 `10°` 观察问题，但不作为最终默认范围。

当前素材缺少下巴底面、鼻孔、颈部遮挡补图和更完整的头发后侧信息，因此第一版的目标是自然的近景跟随，而不是模拟完整三维头模。

## 2. 最可能调整的关键决策

### 2.1 参数定义

新增标准化参数：

```js
headPitch: -1 ... 1
```

约定：

- `-1`：抬头。
- `0`：正面。
- `1`：低头。

内部使用标准化值，界面同时显示“抬头 / 正面 / 低头”，避免把图像坐标、模型旋转方向和用户语义混在一起。

物理角度单独配置：

```js
headPitchRange: {
  upDeg: 7,
  downDeg: 8,
}
```

这样后续可以调整上下范围而不重写关键形数据。

### 2.2 旋转中心与场景层级

点头不能围绕画布中心旋转，应围绕接近双耳连线的头颈轴旋转。第一版从当前图像坐标附近开始校准：

```js
headPivotImage: {
  x: 489,
  y: 410,
}
```

最终值以正面、抬头和低头叠图为准，不把试算值写死在渲染逻辑里。

场景层级调整为：

```text
scene
├── bodyGroup
│   ├── neck
│   └── topwear
└── headPosePivot
    └── headContent
        ├── back_hair
        ├── face
        ├── ears
        ├── facial features
        ├── front_hair
        └── headwear
```

其中：

- `headPosePivot` 负责统一的 X/Y 旋转。
- `headContent` 用相反位移把素材放回原位置。
- `neck` 和 `topwear` 默认不跟随头部刚性旋转，而通过呼吸和接缝补偿保持稳定。
- `headPosePivot.rotation.order` 初步使用 `YXZ`，让左右转头与上下点头组合时更符合头部运动直觉。

### 2.3 A/B 视觉原型

在扩展完整模型前，先做两个低成本版本：

#### A：纯曲面旋转

- 复用当前统一 Z 曲面。
- 围绕耳轴增加 X 方向旋转。
- 不增加脸型、五官或头发关键形。
- 用来确认方向、枢轴、幅度和数学投影是否正确。

#### B：手工点头关键形

在 A 的基础上增加：

- 脸型和下巴校正。
- 眼睛、眉毛、鼻子、嘴的纵向视差。
- 前发、后发、耳朵的独立校正。
- 下巴与脖子接缝补偿。
- 必要时的局部缩放与遮挡修正。

A/B 的第一道视觉门是：管理员确认 B 的点头感确实优于纯曲面旋转。未通过前不进入九宫格组合和正式动作接入。

### 2.4 与 HeadYaw 的组合模型

不为每个姿态保存一整套重复网格，而使用“轴向关键形 + 四角残差”：

```text
             HeadYaw
          -1    0    1
Pitch -1  ↖    ↑    ↗
       0  ←    •    →
       1  ↙    ↓    ↘
```

数据分为：

1. 左右轴关键形：已有 `yaw -1 / 0 / 1`。
2. 上下轴关键形：新增 `pitch -1 / 0 / 1`。
3. 四个角的残差：只记录对角姿态相对两个轴叠加后仍需修正的部分。

推荐合成形式：

```js
finalOffset =
  yawAxisOffset(yaw) +
  pitchAxisOffset(pitch) +
  cornerResidual(yaw, pitch)
```

其中 `cornerResidual` 在任一轴为 `0` 时必须为 `0`。这种数据结构等价于可调的 3×3 姿态网格，但不会复制九份完整模型。

## 3. 点头的视觉拆解

### 3.1 脸型

抬头时：

- 下巴在画面中略向下并变宽一点。
- 脸部下半段纵向略拉长。
- 眼睛到下巴的距离增大。
- 头顶和额头视觉占比略减。

低头时：

- 下巴略向上并收窄。
- 脸部下半段纵向压缩。
- 额头和头顶视觉占比增加。
- 下巴与脖子之间更容易出现接缝或穿帮，需要单独补偿。

脸型变化必须通过局部网格控制点完成，不能只移动整张 `face`。

### 3.2 五官纵向视差

五官不能作为一个整体等距移动。第一版按深度和所在曲面位置区分：

- 眼睛与眉毛：跟随额面旋转，并有轻微纵向压缩。
- 鼻子：因为更靠前，移动幅度应比脸部底纹更明显。
- 嘴：跟随下半脸移动，但不能与鼻子完全同速。
- 耳朵：靠近旋转轴，纵向移动最小。

关键检查不是“移动了多少像素”，而是眼睛、鼻子、嘴、下巴之间的距离是否形成可信的透视变化。

### 3.3 眼睛形变

上下点头时，眼睛除了纵向移动，还需要轻微纵向压缩：

- 抬头时，上眼睑与眼球整体可以略向下压。
- 低头时，眼睛在脸上的相对位置上移，远离镜头的眼球表面纵向可略压扁。
- 左右眼仍需保留当前 HeadYaw 的近眼 / 远眼横向透视规则。

眨眼和眼球注视属于局部动作，应在姿态关键形之后叠加，确保点头时仍能正常闭眼和看向指针。

### 3.4 头发与额头

前发不能只跟着脸平移：

- 发根更接近头部曲面，应跟随头顶旋转。
- 发梢覆盖眼睛和脸颊，需根据点头方向产生独立位移。
- 低头时前发视觉上更容易遮住眼睛。
- 抬头时额头区域会相对减少，发梢与眉眼的距离需调整。

后发主要维持头部轮廓，但在下颌和颈部附近要检查遮挡顺序。

### 3.5 下巴、脖子与衣领接缝

这是上下点头最容易失败的区域：

- 低头可能露出当前素材没有绘制的下巴底面。
- 抬头可能拉开下巴与脖子之间的缝隙。
- 脖子如果和头部一起刚性旋转，会像贴纸。
- 脖子如果完全不动，又可能与脸部断开。

第一版采用保守组合：

1. 头部旋转。
2. 下巴附近脸型局部校正。
3. 脖子顶部做小幅纵向缩放或位移补偿。
4. 严格限制点头角度，避免暴露不存在的纹理。

若仍无法消除接缝，再进入素材补充方案，而不是无限拉伸现有图片。

## 4. 数据结构计划

### 4.1 参数配置

在模型配置中增加：

```js
pose: {
  yaw: {
    limitDeg: 12,
  },
  pitch: {
    upDeg: 7,
    downDeg: 8,
    pivotImage: [489, 410],
  },
}
```

### 4.2 关键形配置

每个部件只保存稀疏控制点位移：

```js
pitchKeyforms: {
  '-1': { /* 抬头控制点偏移 */ },
  '0':  { /* 必须为零或省略 */ },
  '1':  { /* 低头控制点偏移 */ },
}
```

组合修正保存为：

```js
poseCornerResiduals: {
  'up-left': {},
  'up-right': {},
  'down-left': {},
  'down-right': {},
}
```

模型数据只描述形状，不包含 Three.js 对象或运行时状态，保证可测试、可序列化和可回滚。

### 4.3 顶点更新顺序

统一约定渲染顺序：

1. 从不可变的正面基础顶点开始。
2. 应用共享 Z 曲面。
3. 插值 HeadYaw 轴关键形。
4. 插值 HeadPitch 轴关键形。
5. 应用当前象限的角落残差。
6. 应用眨眼、嘴型、呼吸、眼球注视等局部动作。
7. 通过 `headPosePivot` 应用统一的 X/Y 数学旋转。

每帧都从基础顶点重算，禁止在上一帧结果上累积，以免长期运行后漂移。

## 5. 分阶段实施

### 阶段 0：冻结 HeadYaw 基线

- 保存当前正面、左右端点截图。
- 记录当前 HeadYaw 参数范围和旋转中心。
- 确认现有自动测试、构建和浏览器控制正常。
- 把新增问题和临时折中记录到 `implementation-notes.md`。

完成条件：后续任一阶段都能快速判断点头改动是否破坏左右转头。

### 阶段 1：建立 HeadPitch 数学原型 A

- 在参数控制器中增加 `headPitch`。
- 把现有只支持横向枢轴的 `headGroup` 改为二维枢轴的 `headPosePivot`。
- 增加 X 方向旋转并保持正面像素不变。
- 页面增加抬头、正面、低头按钮和独立滑杆。
- 指针控制先保持可切换：横向控制 yaw，纵向控制 pitch。

完成条件：

- `pitch = 0` 与当前正面完全对齐。
- 耳轴附近移动最小。
- 抬头、低头方向符合界面语义。
- A 模式能直观看出纯数学旋转的局限。

### 阶段 2：制作关键形原型 B

按优先级逐项增加：

1. 脸型和下巴。
2. 鼻子与嘴的纵向视差。
3. 双眼和眉毛的纵向位置与压缩。
4. 前发和额头覆盖关系。
5. 后发、耳朵和头饰。
6. 下巴与脖子接缝补偿。

每一项都先只做抬头、正面、低头三个状态，再插值中间值。

完成条件：B 模式在 `-1 / -0.5 / 0 / 0.5 / 1` 五个位置连续、无跳变，并明显比 A 更像头部在空间中转动。

### 阶段 3：A/B 视觉决策门

并排提供以下画面：

- A 正面 / 抬头 / 低头。
- B 正面 / 抬头 / 低头。
- B 的网格视图。
- 下巴与脖子局部放大图。

管理员确认：

- 点头幅度是否够用。
- 脸型是否仍保持角色特征。
- 低头时是否像缩放或贴纸。
- 是否需要补静态素材。

若 B 未通过，此处调整模型，不进入组合姿态。

### 阶段 4：组合 HeadYaw 与 HeadPitch

- 保留左右轴和上下轴的独立关键形。
- 验证四个对角姿态。
- 只为确有问题的部件增加角落残差。
- 优先修正脸型、眼睛、鼻子、前发和颈部接缝。
- 不为看不出差异的部件创建无意义数据。

必须检查九个基准姿态：

```text
抬头左转   抬头正面   抬头右转
平视左转   平视正面   平视右转
低头左转   低头正面   低头右转
```

完成条件：四个角没有网格折叠、眼睛越界、脸型突然跳变或头发穿脸。

### 阶段 5：复用现有局部动作

- 眨眼在所有九个基准姿态下可用。
- 眼球追踪不越出眼眶。
- 嘴型变化不破坏鼻子到下巴的透视。
- 呼吸主要作用于身体和颈部，不重复推动头部。
- HeadYaw / HeadPitch 更新不触发 React 每帧重渲染。

完成条件：姿态和局部动作可以同时播放，且不存在明显的参数覆盖顺序错误。

### 阶段 6：输入与交互

- 鼠标或触控位置同时映射 yaw 与 pitch。
- 提供独立开关和归零按钮，方便排查单轴问题。
- 保留 A/B 模式切换和网格显示。
- 对输入增加平滑、死区和最大速度限制。
- 指针离开页面后缓慢回正，不瞬间跳回。

### 阶段 7：验证、性能与收尾

- 运行单元测试和构建。
- 在浏览器检查控制、截图和控制台。
- 记录桌面端与移动端性能。
- 删除只用于调试的重复模型数据。
- 把最终参数范围和偏离计划的决定写入 `implementation-notes.md`。

## 6. 测试计划

### 6.1 自动测试

新增或扩展测试覆盖：

- `headPitch` 归一化与边界钳制。
- 抬头 / 低头非对称角度映射。
- `pitch = 0` 时顶点和旋转完全回到基线。
- 旋转枢轴点在纯数学旋转下保持稳定。
- 上下关键形三点插值连续。
- 四角残差在任一轴为零时不生效。
- 九宫格组合不会产生 `NaN`、非法索引或反向三角形。
- 短时间连续更新后不会产生累计漂移。

### 6.2 浏览器检查

- 滑杆、按钮和指针控制方向一致。
- A/B 切换不改变当前参数值。
- 网格开关能显示真实变形网格。
- 正面状态与当前已提交版本叠图一致。
- 控制台无错误和重复警告。

### 6.3 视觉截图矩阵

至少保存：

- A：抬头、正面、低头。
- B：抬头、正面、低头。
- B：四个对角姿态。
- B：抬头与低头的网格图。

## 7. 视觉验收标准

### 必须满足

- 正面状态相对当前基线无可见漂移。
- 点头看起来是头部体积和五官透视在变化，不只是整张脸上下平移。
- 耳朵附近相对稳定，符合旋转轴位置。
- 抬头和低头时鼻子、嘴、下巴的相对距离发生可信变化。
- 前发遮挡随姿态改变，不与脸部完全同速。
- 眼睛仍保持在眼眶内，并能正常眨眼和注视。
- 下巴、脖子、衣领之间没有透明裂缝或明显穿插。
- 从端点回正的全过程连续，无关键形跳变。

### 失败信号

- 整个头像一张卡片绕水平轴翻转。
- 脸只是整体缩放或竖向拉伸。
- 五官全部等距移动，缺乏深度差。
- 低头时下巴直接消失或脸贴进脖子。
- 抬头时脖子与脸断开。
- 对角姿态明显比单轴姿态差一个等级。
- 为追求大角度导致角色脸型失真。

## 8. 风险与盲区扫描

管理员当前已经进入 Web 2.5D 曲面建模的深水区。这里有几件容易在需求中被忽略、但会直接决定效果上限的事：

### 8.1 点头比左右转头更依赖缺失素材

左右转头主要缺脸侧和耳后信息；上下点头会直接暴露下巴底面、鼻子下表面和颈部遮挡。当前切片没有这些信息，所以角度上限必须更保守。

### 8.2 数学正确不等于视觉正确

真实 X 轴旋转只能提供统一曲面投影。二次元角色的脸型、眼睛大小和头发遮挡本身不是严格三维投影，仍需要手工关键形保留角色设计。

### 8.3 透明纹理排序不等于真实遮挡

Three.js 的透明对象即使有 Z 值，也可能受绘制顺序影响。点头加入后必须重新检查前发、脸、耳朵、后发和脖子的渲染顺序，不能只看几何深度。

### 8.4 对角姿态不是两个单轴结果的简单相加

左右与上下分别自然，不代表斜向自然。眼睛、脸侧、下巴和头发最容易在四角产生过度形变，因此计划保留小规模角落残差，而不是假设线性叠加足够。

### 8.5 大角度的正确升级路径是补素材

如果最终希望超过约 `10°` 的明显抬头或低头，建议补充：

- 下巴底面或下颌阴影。
- 鼻子下侧 / 鼻孔的可控图层。
- 更长的脖子与衣领遮挡区域。
- 前发发根和发梢分层。
- 必要时的闭合嘴与张嘴内部层。

不建议用更激进的网格拉伸替代这些信息。

## 10. 偏离记录要求

实施中出现以下情况，需要写入 `implementation-notes.md` 的 `Deviations`：

- 改变抬头或低头的默认角度范围。
- 改变旋转中心或旋转顺序。
- 为消除接缝而让脖子进入头部旋转组。
- 放弃 A/B 结构或九宫格验证。

- 为性能原因调整 React 与渲染器的状态同步方式。

## 11. 完成定义

只有同时满足以下条件，HeadPitch 才算完成：

1. A/B 点头原型已由管理员确认方向。
2. 正面、抬头、低头和四个对角姿态均通过视觉检查。
3. 正面和现有 HeadYaw 基线无可见回归。
4. 眨眼、眼球、嘴型和呼吸能与 yaw/pitch 同时运行。
5. 下巴与脖子接缝没有明显穿帮。
6. 单元测试、构建和浏览器控制台检查通过。
7. 参数、关键形和角落残差均为可序列化配置，不散落在渲染代码中。
8. 已记录最终角度上限、已知素材限制和所有计划偏离。
