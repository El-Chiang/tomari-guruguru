# 网页端 2.5D 手工曲面头像计划

## 1. 目标与结论

本项目最终只在网页中运行，不要求导出 Cubism `.moc3`，也不要求兼容
VTube Studio。因此主线改为：使用现有分层图片，在网页中实现一个面向本角色的
轻量 2.5D 网格渲染器。

目标不是复刻完整 Live2D Cubism，而是补齐当前项目最缺少的能力：

- 图片内部的局部网格变形，而不是整张 PNG 的 CSS Transform。
- 顶点拥有真实 Z 深度的手工曲面。
- `-12° / 0° / +12°` 转头端点的美术修正。
- 五官、前发、后发和耳朵之间的独立视差与遮挡关系。
- 复用现有眨眼、眼球、嘴部、呼吸和参数平滑逻辑。

首版只承诺水平转头 `HeadYaw`。垂直转头、标准 Live2D 格式导出和大角度侧脸
不属于首版范围。

## 2. 最可能调整的关键决策

### 2.1 渲染技术

采用 React + Three.js：

- React 继续负责页面、状态和调试面板。
- Three.js 负责纹理、网格、相机和 WebGL 渲染。
- 首版在 CPU 端计算少量网格顶点并更新 `BufferGeometry`，不先写自定义 Shader。
- 所有透明层使用明确的 `renderOrder`；Z 深度用于透视和视差，不把透明层排序完全
  交给深度缓冲。

选择 Three.js 而不是纯 CSS，是因为 CSS 只能对完整图片做仿射/透视变换，无法让
脸颊、下巴和前额形成不同的曲率。选择 CPU 网格插值，是因为本模型只有约 13 个
图层、每层几十到一百多个顶点，性能充足，而且调试成本远低于 Shader 版本。

### 2.2 模型数据

曲面和动作不硬编码在 React 组件中，独立保存为可版本管理的模型配置。建议结构：

```js
{
  canvas: { width: 1024, height: 1024 },
  parameters: {
    headYaw: { min: -1, default: 0, max: 1 },
    eyeX:    { min: -1, default: 0, max: 1 },
    eyeOpenL:{ min:  0, default: 1, max: 1 },
    eyeOpenR:{ min:  0, default: 1, max: 1 },
    mouthOpen:{ min: 0, default: 0, max: 1 }
  },
  layers: [
    {
      id: 'face',
      texture: '/oc-layers/face.webp',
      crop: { x: 0, y: 0, width: 1024, height: 1024 },
      renderOrder: 40,
      mesh: { columns: 8, rows: 10, surface: 'faceEllipsoid' },
      keyforms: {
        headYaw: {
          '-1': { /* 控制点修正 */ },
          '0':  { /* 中立形状 */ },
          '1':  { /* 控制点修正 */ }
        }
      }
    }
  ]
}
```

每个网格顶点的最终位置由三部分组成：

```text
基础 XY 位置
+ 基础曲面生成的 Z 深度
+ HeadYaw 端点关键形状的插值修正
```

这使“数学曲面”和“二次元美术修正”互不覆盖：曲面负责基础立体旋转，关键形状负责
纠正纯椭球产生的橡皮感。

### 2.3 运行时参数管线

统一参数流，不让鼠标逻辑直接操作某个 DOM 或网格：

```text
Pointer / Idle / Audio
        ↓
ParameterController
        ↓
平滑后的 HeadYaw / EyeX / EyeOpen / MouthOpen / HeadTilt
        ↓
MeshModel.update(parameters)
        ↓
Three.js Render
```

这样可以复用 `src/oc-live.jsx` 已有的鼠标归一化、平滑、随机扫视、自然眨眼和嘴部
目标值逻辑，同时避免未来音频口型与网格实现相互耦合。

### 2.4 原型和正式页面隔离

新增独立实验页，例如 `mesh-turn.html`，不直接替换 `oc-live.html` 或现有主页面。
只有在管理员确认视觉方向后，才把新渲染器接入正式角色组件。

## 3. 素材处理计划

### 3.1 使用本地纹理

WebGL 原型统一读取 `public/oc-layers/` 的本地图片，不使用当前配置中的外部 CDN。
这样可以避免跨域纹理、离线运行和 Canvas/WebGL 安全限制导致的调试差异。

### 3.2 计算有效内容边界

当前图片是全画布透明层，并可能存在远离主体的低 alpha 像素。不能直接把整张
1024×1024 图片当作每个部件的网格范围，否则会再次出现 Cubism 中“框很大、拉很多
但变化很小”的问题。

实现一个素材审计/预处理步骤：

1. 读取每张图片的 alpha。
2. 以明确阈值计算可见内容 bbox。
3. 输出 bbox 报告，不覆盖原始图片。
4. 网格仅覆盖有效 bbox，UV 仍指向原图对应区域。
5. 对阈值附近的细发丝进行人工复核，避免裁掉柔和边缘。

### 3.3 左右部件

为了分别控制远侧眼睛和近侧眼睛，网页模型使用已经拆分的左右眼、瞳孔和眉毛素材。
必要时从 `live2d-work/ichigo/layers-split/` 生成网页用 WebP，并补齐配置：

- `eyelash_L / eyelash_R`
- `irides_L / irides_R`
- `eyebrow_L / eyebrow_R`

原始合并层保留，现有页面不受影响。

## 4. 曲面设计

### 4.1 脸部

脸部使用浅椭球基础曲面，不使用统一圆柱。初始 Z 可由椭球公式生成：

```text
z = depth × sqrt(max(0, 1 - (x / radiusX)² - (y / radiusY)²))
```

然后增加手工深度控制点：

- 额头较平。
- 眼眶略向后。
- 两颊向前形成弧度。
- 下巴收窄并稍向后。
- 脸部外轮廓保留端点关键形状，避免数学椭球把下颌变圆。

### 4.2 五官

- 鼻子使用独立小平面并拥有最大的面部前向 Z。
- 嘴部贴近脸面，但不完全与脸网格共面。
- 左右眼分别使用小网格；远侧眼在端点压缩，近侧眼只做轻微展开。
- 眉毛跟随对应眼眶，但保留独立表情位移。
- 眼球移动发生在眼睛局部坐标内，不能覆盖 HeadYaw 的远近关系。

### 4.3 头发和耳朵

- 后发是脸后的浅曲面壳。
- 前发是脸前的独立曲面壳，不能与脸共用同一 Z 公式。
- 发饰作为前发的子层，但允许更大的 Z 偏移。
- 耳朵位于脸后；转头时近侧耳朵可以更多露出，远侧耳朵可以被脸/头发遮挡。
- 首版优先用固定绘制顺序和透明遮罩解决遮挡；确实需要交叉遮挡时再引入局部 mask。

## 5. 分阶段实施

### 阶段 0：建立基线

- 记录当前 `oc-live.html` 和 `oc-turn.html` 在中心、左端、右端的截图。
- 记录现有构建结果和桌面浏览器帧率。
- 审计所有图层尺寸、alpha bbox、左右拆分层和真实绘制顺序。
- 确认素材坐标系、人物视觉中心和头部旋转中心。

完成标准：有可复现的基线截图、bbox 报告和模型坐标说明。

### 阶段 1：网格渲染基础

- 安装并接入 Three.js。
- 新建独立 `mesh-turn.html` 和对应 React 入口。
- 实现正交/弱透视相机、透明纹理加载、resize 和 DPR 限制。
- 实现规则网格生成、UV crop、renderOrder 和线框调试模式。
- 先以零变形完整还原当前正面合成。

完成标准：`HeadYaw = 0` 时，与现有正面图视觉对齐；无明显接缝、错层和模糊。

### 阶段 2：A/B 低成本曲面原型

原型 A：

- 只给脸、前发、后发设置真实 Z 曲面。
- 仅做数学曲面旋转，不做端点美术修正。

原型 B：

- 在 A 的基础上增加 `-12° / 0° / +12°` 手工关键形状。
- 加入五官独立深度、远侧眼压缩、鼻子视差、脸颊/下巴修正。

同一页面提供 A/B 切换、`HeadYaw` 滑杆、线框开关和正面叠图。管理员先选择
视觉方向，未确认前不进入正式集成。

完成标准：在同一素材上能明确看出 A 的纯曲面效果和 B 的艺术修正效果差异。

### 阶段 3：手工曲面调试工具

- 调整基础深度参数：脸宽高、最大深度、前后发壳层深度。
- 支持选层、显示控制点、拖动控制点的 XYZ 或关键形状偏移。
- 支持锁定对称点、恢复单层和恢复单个端点。
- 能把当前调整结果导出为模型配置文本，避免只存在内存里。
- 调试工具只出现在实验页/开发模式，不进入正式 UI。

完成标准：刷新前导出、写回配置后，能稳定复现同一曲面和端点形状。

### 阶段 4：完整 HeadYaw 组合

按照以下顺序完成并验收：

1. 脸部轮廓和下巴。
2. 鼻子、嘴和眉毛视差。
3. 左右眼远近变化。
4. 耳朵露出/遮挡。
5. 前发、后发和发饰曲面。
6. 颈部连接和头部旋转中心。

加入运行时修正：

- 曲面经过相机投影后的基础位置。
- 三个 HeadYaw 关键形状之间的插值。
- 近侧/远侧五官的非对称倍率。
- 必要的 opacity、mask 或 renderOrder 切换。

完成标准：`-12° / 0° / +12°` 都没有明显穿帮，连续拖动时没有跳点。

### 阶段 5：复用现有 Live 动作

从 `src/oc-live.jsx` 提取并复用参数逻辑：

- 鼠标方向归一化和平滑。
- 随机眼球扫视。
- 自然眨眼与二次眨眼。
- 连续嘴部开合目标值。
- 头部倾斜、呼吸、上下浮动和头发轻摆。

动作组合优先级：

```text
基础曲面
→ HeadYaw
→ 端点美术修正
→ 眼球/眼皮/嘴部局部动作
→ HeadTilt / 呼吸 / 整体浮动
```

完成标准：转头时眨眼、看向光标和嘴部开合仍然正常，不发生参数互相覆盖。

### 阶段 6：正式接入与回退

- 将渲染器封装为独立角色组件，不把 Three.js 细节散落到页面组件。
- 保留现有分层 DOM/CSS 实现作为回退，直到新版本完成视觉验收。
- 在项目正式入口中通过单一配置切换旧版/新版，确认后再删除实验开关。
- 更新 README 中的运行方式、素材要求和模型调节说明。

完成标准：正式页面可使用新模型，旧页面和原有 25 方向版本仍可正常构建。

### 阶段 7：验证与性能

- `npm run build`、`npm run verify:pages`（若脚本适用）通过。
- Chrome 和 Safari 手工检查透明边缘、DPR、resize 和后台恢复。
- 桌面目标 60 FPS；普通移动设备目标至少稳定 30 FPS。
- 限制 DPR 和纹理重复上传，卸载组件时释放 geometry/material/texture。
- 检查本地静态部署和 GitHub Pages base path。
- 保存中心、左右端点及动作组合截图/短录屏作为验收证据。

## 6. 视觉验收标准

### 必须满足

- 正面中立姿态与原图基本一致，不能为了转头破坏正面观感。
- 左右转头不是整个平面一起倾斜；脸颊、下巴、鼻子、眼睛和头发具有不同运动量。
- 近侧眼与远侧眼大小不同，但不能出现明显挤扁或拉长。
- 鼻子相对脸有可见但克制的视差。
- 脸部外轮廓随方向改变，远侧轮廓压缩、近侧轮廓展开。
- 前发与脸不是同一曲面，转动时能感到前后关系。
- 下巴与脖子连接稳定，没有裂缝或漂移。
- 从 `-12°` 连续移动到 `+12°` 时没有突然跳变。

### 失败信号

- 仍然像一张纸贴在圆柱上旋转。
- 所有图层移动方向和幅度一致。
- 只有眼睛/鼻子平移，脸部轮廓没有改变。
- 为了增强效果而产生大面积纹理拉伸。
- 端点好看，但中间插值出现脸型塌陷。
- 正面无法回到原始构图。

### 角度边界

首版视觉设计角度是约 `±12°`，参数仍可使用 `-1..1`。UI 不应把参数值 `±30`
误解成真实物理角度 `±30°`。如需扩展到更大角度，应先评估补充侧脸、耳侧和发际线
素材，而不是继续强拉当前正面图。

## 7. 测试清单

### 自动检查

- 网格索引和 UV 均在合法范围。
- 所有模型配置引用的纹理存在。
- `HeadYaw = 0` 时关键形状修正为零或符合中立定义。
- 参数超界会被 clamp。
- WebGL 资源在卸载时释放。
- 正式构建包含新入口且现有入口不丢失。

### 人工检查

- A/B 原型在 `-12° / 0° / +12°` 的截图比较。
- 线框模式检查脸、前发、后发的曲率方向。
- 连续快速往返转头检查抖动和穿层。
- HeadYaw 与眨眼、眼球移动、嘴部开合的两两组合。
- 不同窗口尺寸、DPR 和浏览器缩放下的清晰度。
- CDN 断网时仍能从本地资源运行。

## 8. 风险和应对

### 纹理缺失区域

正面切图没有侧脸隐藏像素。首版限制在约 `±12°`；超过边界不继续拉伸。确需更大
角度时，新增方向差分纹理并进行交叉淡入，而不是把当前曲面无限外推。

### 透明层排序

透明材质的真实 Z 与绘制顺序可能冲突。首版以明确 `renderOrder` 为主、Z 负责投影；
只有局部交叉遮挡再使用 mask 或拆层。

### 全画布稀疏 alpha

网格必须按有效 bbox 建立，不能让稀疏像素扩大变形范围。预处理只输出报告和网页
派生素材，不覆盖原始切片。

### 调参不可复现

所有手工调整最终写入模型配置。调试面板中的临时状态不能作为完成状态。

### 范围膨胀

不实现通用 Live2D 编辑器、物理引擎、Cubism 文件导入器或任意角色自动绑定。
首版以当前 ichigo 素材和 HeadYaw 视觉质量为唯一主线。

## 11. 目标完成定义

只有同时满足以下条件，目标才算完成：

1. 独立实验页可运行，并提供 A/B 曲面比较。
2. 管理员确认 B 方案或明确选择的替代方案。
3. 完成约 `±12°` 的连续 HeadYaw，视觉上不再是整张平面旋转。
4. 现有眨眼、眼球和嘴部参数已接入新网格模型。
5. 正式构建通过，现有页面无回归。
6. 有截图/录屏和性能数据作为验收证据。
7. 所有手工曲面和关键形状调整均已固化到配置文件。

建议目标描述：
